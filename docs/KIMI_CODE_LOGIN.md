# Kimi Code 多账号额度、登录续期与恢复

[English](./KIMI_CODE_LOGIN.en.md)

## 本机登录与多个 API Key 一起查看

在 **权益中心 → 权益设置 → Kimi Code** 展开卡片：

1. 保留“本机 CLI 登录”，它在查询时读取当前登录；不需要复制登录令牌。
2. 每个其他账户点击“添加 API Key 账户”，填写便于识别的名称和 **Kimi for Coding API Key**。
   使用 Kimi Code 控制台创建的 Key，不是 Moonshot 开放平台 Key。
3. macOS 可将 Key 保存在系统钥匙串；也可给各账户指定不同的环境变量名。
   变量必须由启动看板的进程继承。没有系统钥匙串的平台使用环境变量，不明文保存 Key。
4. 保存并刷新后，通过“查看账户”切换额度；名称、凭据、手动标注的权益与支出均属于各自连接。
   某个 Key 过期只影响该连接，其他账户仍会显示。已保存的 Key 留空即可保留。

一个账户下的多个 Key 与设备通常共享套餐额度，不是每个 Key 各有一份。
接口返回可验证的账户 ID 时，总览和额度历史会对同账户连接去重；没有身份依据时不会猜测合并，
请勿将这些连接当作独立套餐重复相加。旧的单账户设置会迁移为一个连接；旧 Web Token 继续兼容，
若旧配置实际填的是 Coding API Key，请将连接方式改为 API Key 并重新填写。

新套餐只展示官方实际返回的 5 小时、月度等窗口。未返回周额度不代表查询失败；仍兼容旧周额度。
月度窗口没有明确时长时，不会虚构 30 天，也不会换算成 Token 上限。

### 为什么暂不能按 Key 统计历史 Token？

Kimi CLI、OpenCode、WorkBuddy、ZCode 等多个客户端可能共用同一 Key；客户端名、模型名和当前
配置都不能证明某条历史请求使用了哪个 Key。现有扫描日志未提供可靠的逐请求 Key 身份，
Coding 额度接口也不是逐 Key 的 Token 明细账。因此权益中心不把 Agent 级 Token 自动归给某个
Kimi 账户，显示“本机用量未关联”；用量中心原有的全部 Token 统计不受影响。
未来只有在日志提供稳定的请求级 Key 标识后，才可新增本机专用、脱敏的 Key 维度；不会回填猜测值，
更不会把真实 Key 写入记录、导出、诊断或社区同步。

Kimi Code 额度默认复用官方 CLI 的本机登录，按以下顺序取第一个存在的
`credentials/kimi-code.json`：`$KIMI_SHARE_DIR`、`$KIMI_CODE_HOME`、`~/.kimi-code`（CLI 2.x）、
`~/.kimi`（CLI 1.x）。仅当官方 CLI 使用非默认主目录时才需要设置 `KIMI_CODE_HOME` 或 `KIMI_SHARE_DIR`。

## 续期机制与轮换风险

Kimi 的 refresh token 是轮换的：每次续期都会下发新的 refresh token，旧令牌随即作废。这意味着：

- 只在本工具内存中续期、不写回文件，会让 CLI 保存的旧 refresh token 失效，影响 CLI 自己的登录；
- 把新令牌写回文件，则可能与 CLI 自身的续期相互竞争。

本工具选择参与续期，并针对上述风险做了收敛：

- 续期在文件级进程锁内串行执行（Windows 与 `KIMI_DISABLE_OAUTH_LOCK=1` 除外）；
- 持锁后重新读取凭据文件：若 CLI 已在此期间写入新登录，则直接采用，不重复续期；
- 续期请求被拒绝（HTTP 400）时，稍候重读文件，CLI 侧已轮换出的新登录会被采纳；
- 写回使用临时文件加原子改名，权限 0600，并保留本工具不认识的字段；
- 访问令牌默认在到期前至少 300 秒即触发续期；额度接口返回 401 时强制续期一次并重试查询；
  续期只在查询时按需发生，没有后台进程。

官方 CLI 仍是登录的所有者。极端情况下本工具与 CLI 几乎同时续期，可能出现单次查询失败，
按下面的恢复步骤重试即可，不会损坏 CLI 登录。

## 登录过期时的恢复

CLI 的访问令牌生命周期很短；CLI 退出后不再有进程替它续期，下一次查询就可能过期。此时：

1. 运行 `kimi` 重新登录（若 CLI 要求则完成登录流程）；
2. 重新发起查询——本工具每次查询都会重读凭据文件，**无需重启**；
3. 无人值守时可另加一个 API Key 连接，使用自己的环境变量或系统钥匙串，
   不依赖 CLI 侧文件状态。API Key 只发给 Coding 额度接口，不会进入网页登录或 OAuth 续期流程。

凭据文件只在本机读取。排障时不要把 `credentials/kimi-code.json` 的内容发到 Issue、
聊天或社区；过期时运行 `kimi` 换取新登录即可。
