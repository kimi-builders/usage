# Kimi Builders Usage 0.5.0

> [English](./RELEASE_NOTES_0.5.0.en.md)

`0.5.0` 把本机扫描、社区连接和同步范围整合为一套可由用户直接控制的工作流。它仍然
默认只在本机工作：连接设备不等于上传，只有明确标记为“本机并同步”的 Agent 才会进入
后续同步。

## 数据范围与隐私控制

- 为每个 Agent 增加“关闭 / 仅本机 / 本机并同步”三种模式；关闭的来源不会扫描，仅本机
  来源只参与当前设备分析，新支持的来源不会静默加入社区同步。
- 已连接的旧安装会保留原有同步覆盖；用户作出明确选择后，以新策略为准。
- 项目名、会话标识、对话内容、完整路径和供应商凭据继续遵守既有隐私边界。
- 本地 Dashboard 集中管理扫描范围、社区连接、后台同步、设备撤销和云端设备数据删除。

## 设备授权与同步可靠性

- 设备验证码可在 Dashboard 刷新后继续显示，明确展示有效期、过期、拒绝和重试状态；
  验证码只存在于当前本机进程，不进入浏览器存储或配置文件。
- 断开设备会先尝试撤销远端 Key；社区不可达时保留本机连接，并提供带风险说明的显式
  本机清除兜底，不会悄悄留下用户看不见的有效 Key。
- checkpoint 绑定社区目标和设备。无法证明增量基线一致时，普通同步安全停止并要求用户
  确认一次完整重放，避免把不完整历史当成已同步。
- Dashboard 的立即同步增加运行耗时、真实的不确定进度，以及成功、无变化、部分成功、
  隔离异常记录和失败结果；失败来源继续保留社区旧数据。

## Dashboard 体验

- 社区连接状态覆盖等待批准、验证码过期、拒绝、失效和已连接，不再把“已连接”误解为
  “已同步”。
- 长同步弹窗使用固定标题和独立内容滚动区，滚动条不再穿过标题圆角；Agent 范围、同步
  操作和远程数据管理按真实内容高度排列，不发生覆盖。
- 中英文 README 补充连接验证码生命周期、首次连接与同步的边界说明。

## 升级

无需全局安装，直接运行最新版：

```bash
npx @kimi.builders/usage@latest dashboard
```

已安装后台同步的用户应刷新调度器记录的运行路径：

```bash
npx @kimi.builders/usage@latest daemon restart
```

升级不会删除本地历史、社区连接或已有远端数据。首次打开新版 Dashboard 时请检查每个
Agent 的数据模式，再决定是否执行社区同步。
