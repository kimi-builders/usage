# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## Durable product decisions

- Subscription Center is a first-class destination. Usage Center keeps only a compact health/entry strip; do not place the full quota product above Usage analytics again.
- Subscription analysis uses the complete local source history and does not inherit temporary Usage Center filters.
- Keep three data classes visually and semantically separate: provider-reported quota facts, locally observed Token usage, and derived capacity estimates.
- ChatGPT Pro, Claude Max, and similar subscriptions must not be described as having an official fixed Token cap when the provider only exposes utilization. Capacity and model-only numbers are estimates, with their window, sample quality, assumptions, and uncertainty visible.
- Actual subscription spend is user-entered. Never guess a user's plan price, discounts, tax, currency, or renewal date.
- Future recommendations must answer “what did this cost, what capacity/value did it produce, and what should I change?” with traceable evidence; they must not mutate subscriptions or credentials automatically.
- Quota history is backend-owned, sanitized, and separate from Agent usage logs. Persist only quota window facts needed for longitudinal analysis; never persist account identity, credential/source paths, raw responses, or provider errors in that history file.
- Keep quota history bounded: recent points may be 15-minute resolution, medium-term points hourly, and older points daily. A cached page read must not append a duplicate observation.
- Pace and value signals must identify their evidence window. Stale history may remain visible after a provider error, but must not produce a current-cycle forecast or prescriptive recommendation.
- Never compare CNY and USD subscription value by silently inventing an exchange rate. Show currencies separately until the user supplies or the product versions an explicit rate source.
- Cross-cycle capacity ranges may use only completed quota cycles sampled close to reset with at least 90% local-log coverage. Show the eligible-cycle count, interval method, and confidence; never promote a partial cycle into a historical range.
- Renewal forecasts require a configured renewal date, at least 10% elapsed period, and at least 90% local-log coverage. Keep actual-to-date and projected figures visibly distinct.
- Describe similar 30-day model-family distributions as workload-overlap review candidates, never as proven duplicate subscriptions. Remind users that web usage, other devices, team benefits, and non-Token features are outside the evidence.
- Treat connected accounts as a benefit portfolio, not a paid-subscription count. Every enabled account may be classified as paid, free, promotional/trial, organization-provided, or unknown; unknown must never be silently treated as free, paid, or unlimited.
- Only explicitly paid accounts enter personal spend, renewal, and paid-without-local-usage analysis. Free, promotional, and organization-provided benefits still contribute Token throughput and workload evidence, but API-equivalent value must not be presented as realized savings.
- Official quota observability is independent from local Token observability. If a provider or account does not expose a stable quota window, keep local usage and value analysis available, label the official balance unobservable, and never infer remaining quota from absence.
- Personal budget targets are user-declared data, independent from provider facts, locally observed usage, and derived estimates. Never mix a personal target into any of those three evidence classes or present it as a provider limit or bill.
- Runaway alerts use exact hourly Token buckets only. Do not claim session-level Token spikes until the local snapshot has an explicit, tested session-to-Token relationship; time-window overlap is not reliable attribution.
- The Dashboard is the primary human control surface for novices; CLI commands remain an equivalent automation and advanced-operations surface. Ordinary connection, source-scope, one-shot sync, background-sync, disconnect, and current-device cloud-data controls must not require terminal use.
- Describe local choices as “data sources” and “scan scope,” not as a privacy toggle. Reserve ownership and privacy language for remote sync, remote retention, public participation, and destructive data controls.
- Per-source scan and community-sync policy is explicit and independent: Off means no parse, Local means local analysis only, and Local + sync permits upload to the user's community account. Stopping sync never deletes cloud history; deletion requires a separate confirmation. Account-level visibility separately decides whether uploaded aggregates participate in public surfaces.
- Existing connected installations must preserve their former sync coverage when source policy is first introduced. Once a policy is explicit, newly supported automatic sources default to Local only, and explicit-opt-in sources default Off. No new source may silently join sync or public participation.
- Device source policy and account-level public visibility are different scopes. The local Dashboard may manage the current device and link to account settings, but must not imply that a device toggle changes all devices or leaderboard visibility.
- Device authorization codes are short-lived, process-memory state. The local Dashboard must recover an in-progress authorization after a dialog close or page refresh while that service is still running, show its expiry, and never persist the device secret in browser storage. “Connected” never implies “synced.” Disconnect revokes the remote device key before forgetting local credentials; an explicit local-only fallback must warn that the remote key may remain active when the community is unreachable.
- One-shot sync feedback belongs beside the action that started it: show an honest indeterminate running state with elapsed time, then a persistent success, partial-success, or failure summary. Long dialogs keep their scrollbar inside the rounded content viewport; scrollbars must not cut through the title area or outer corners.
- Compact usage and count values follow the interface locale everywhere they are shared: Chinese uses Intl compact units such as 万/亿, while English keeps K/M/B. The Usage Center, charts, records, insight cards, export summary, and share poster must use the same formatter rather than hand-written thresholds. Share-poster copy follows the interface language completely; never render the English poster with Chinese labels.
- Account-based quota integrations belong in the same Detected / All-platform provider cards as every other provider; expand connection controls in-place instead of creating a separate featured strip above the catalog.
- OpenCode quota means OpenCode Go. Treat account name, Cookie, `wrk_…` Workspace ID, benefit type, actual price, currency, billing cycle, and renewal date as one indivisible per-account configuration. Every added account must provide all three connection fields before quota lookup; never share connection or subscription metadata across accounts. Migrate legacy provider-level subscription metadata only once to the previously active account.
- Do not expose a Windsurf/Devin subscription-quota provider until there is a stable, independently verified integration. This does not remove any separate local Agent-usage source or icon.
- Keep Dashboard data visualization visually synchronized with the community Usage Center. Use the official Kimi semantic palette, one blue focus series with neutral comparisons, dotted low-contrast grids, direct peak labels, sequential heatmaps, and LobeHub brand marks through `ToolGlyph`; preserve local-only attribution and never infer missing project data.
